## 这套文档的核心主张

一句话：**宿主（渲染 / 窗口 / 输入 / 装饰）应当是可替换的一层，内核只通过声明式的接口找它。**

文档里反复回到的几个点：

- **能力位 + 自审 + 一致性测试**：后端拿不到某个能力时要能被发现，而不是静默降级。
- **「指标正常但已经废了」是最致命的故障**：帧率、内存全都正常，画面却是空的。
  文档里列了三类自检项（输入区、资源增长、渲染输出），每一条都对应一次真实踩坑。
- **降级要看得见**：静默失败等于用户以为程序坏了。
- **别过早多线程**：实测里单核跑到约 114% 才出现线程瓶颈，在那之前多线程只是把复杂度搬进来。

### 文档里的数字来自实测，不是估算

| 量 | 值 |
|---|---|
| 一帧里「顶点过变形链」的成本 | 约 0.14 ms |
| Qt 调用 + 建对象的成本 | 是上者的约 **200 倍** |
| 合成绘制（不变图层复用） | 约 0.23 ms |
| 空白页面的 Chromium 底盘 | **383 MB** |
| 换掉宿主后宠物端内存 | 约 509 MB → 约 78 MB |

（具体口径与前提写在对应文档里；**这些数字绑定当时那台机器与那个版本**，换环境请重测。）
